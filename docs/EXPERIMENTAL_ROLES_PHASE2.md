# 実験的キャラクター B組: 気球乗り / バンシー / 賞金稼ぎ / カニバル

この更新は直前の実験的キャラクターA組ビルドを土台に、4役をスクリプトメーカー専用キャラクターとして追加します。TB / BMR / S&V の組み込みスクリプトは変更しません。無神論者は今回の対象外です。

## 記号

- 軽業師: `軽`
- 錬金術師: `錬`
- アルサーヒル: `ア`
- 記憶喪失者: `記`

内部 RoleId / RoleTag / event kind / storage key / solver metadata は英語のままです。日本語化するのはUI表示だけです。

## 気球乗り

- N1以降、毎夜1人を記録します。
- 健康なら前夜に示された人とは異なる character type でなければなりません。
- Spy / Recluse の登録変更は候補世界側で考慮します。
- Vortox下では健康な町人情報として偽である必要があるため、前夜と同じ type を許す側を採用します。
- セットアップは通常人数と `+1 Outsider / -1 Townsfolk` の両方を合法候補として保持します。

## バンシー

- デーモンによる夜死亡で健康な能力が発動した候補世界では `bansheeActive` を保持します。
- 発動後は死んでいても1日2回指名できます。
- 発動後は各投票で2票として数えます。
- この投票は通常の死者票を消費しません。
- 処刑死や、明示された非デーモン能力による夜死亡では発動しません。
- UI側では通常の `night_death` をデーモン襲撃として扱う既存入力規約を利用します。非デーモン夜死亡は sourceRoleId を付けて記録してください。

## 賞金稼ぎ

- セットアップ候補世界ごとに、町人1人を実際に悪陣営へ変更します。
- そのため「町人キャラクター = 必ず善」という前提は使いません。
- 善悪画面の悪確率は、この追加の悪町人候補を含む可能世界から自然に上がります。
- N1に悪陣営1人を記録します。
- その人が死亡した後の夜だけ、新しい悪陣営1人を記録できます。
- 同じ人を2回知らされる候補世界は除外します。
- 酔い/毒なら誤情報を許します。

## カニバル

- 最後に「処刑され、実際に死亡した」プレイヤーの実役職能力を候補世界内で取得します。
- 善の処刑死ならその能力を得ます。
- 悪の処刑死なら、次に善のプレイヤーが処刑死するまでカニバルは毒状態として扱います。
- UIはプレイヤー本人が実能力を知らないルールに合わせ、直近の処刑死プレイヤーの公開 role claim を能力入力の仮説として再利用します。
- その仮説が実役職と一致するかは候補世界側で検証します。
- Monkについては実際の保護ロジックまで接続済みです。直近の善Monkが処刑死した場合、次夜のカニバルはMonkの対象入力を使え、健康ならデーモン襲撃を防ぎます。
- 情報役職については既存の情報入力UIを再利用できます。

## 記憶喪失者タグ

新タグは内部英語名のまま保持し、UIでは日本語ラベルを表示します。今回追加した性質も半分割り質問の候補に含めています。

## 今回の境界

- Philosopher / Bounty Hunter の公式jinxによる「町人が悪になる可能性」は今回未実装です。今回のセットアップ悪町人は実Bounty Hunterが初期配置に存在する場合です。
- Cannibalは直近のexecuteeの公開claimをUIプロキシに使うため、未claimの能力はUIで自動推測しません。solverは実役職を使います。
- Cannibalの全役職に対する特殊な一度きりUI再開/jinxを網羅したわけではありません。Monkと既存情報UIは接続済みです。
